# Conversion preservation measurements

[`cases.yaml`](cases.yaml) declares inputs, explicit profiles/reference contexts and
expected outcomes. [`report.json`](report.json) is generated by
`just conversion-report` and must reproduce under `just conversion-check` in CI.
For reconstructed outputs it records which column spellings changed and how many
records changed, separately from the preserved interpreted fields.
See the [profile contract and worked commands](../../docs/conversion-profiles.md).

| Case | Adapter outcome | Source recovery | Mapped-field reconstruction |

The GenBank source-text inspection finds six accession-versioned records, 38 feature
location lines, six containing `join`, seven with partial endpoints, and two repeated
qualifier keys within features. Those are observations of this file, not the results
of a full INSDC parser or format validator. The format's expressive power is not
limited by our current adapter coverage.

Both exporters refuse edited instances. No lossy export is implemented, so rejected
cases have diagnostics and no converted output, rather than a fabricated lossless
result. The report records zero losses only for the operations actually performed;
`not-attempted` is not success. Nonfeature records are preserved by the source layer;
the separate reconstruction claim covers mapped feature fields and relationships.
Neither byte recovery nor a successful query establishes full biological equivalence.

Dependency versions and profile-file checksums are recorded in the report. Source
versions, attribution, licenses and checksums live in the [corpus index](../../corpus/index.yaml).
Query timing is deliberately not part of this preservation report.

The [protein-relative example](../../docs/protein-relative-profile.md) retains the
structural GFF and FASTA used to generate its context. The report records that
context's SHA-256 as a conversion input; tests regenerate it from both companion
sources. Its amino-acid coordinates remain separate from genomic CDS coordinates.
